# Technical audit — 2026-08-11

Full audit of `Go-DDD-Scaffold`: CLI, generated project templates, VS Code extension, CI/CD, Docker. Every finding was **reproduced** before being fixed and **re-verified** after.

## Summary

The generator was **broken on any modern installation** and, when it managed to run, **produced a project that did not compile**. Three independent defects added up:

```
  scaffold init
       │
       ├─ init() of the scaffold package
       │     └─ panic if $GOPATH == ""             ──►  [1] CLI dead out of the box
       │
       ├─ target = filepath.Dir(os.Args[0])
       │     └─ the BINARY's dir, not the CWD     ──►  [2] files generated in the wrong place
       │
       ├─ templates read from
       │     $GOPATH/src/github.com/Allan-Nava/Go-DDD-Scaffold/template/
       │     └─ missing after `go install`         ──►  [3] no template found
       │
       └─ html/template on Go code                 ──►  [4] escaped sources
              │
              ▼
        generated project: 9 compilation errors    ──► [5] unusable
```

After the fixes: templates in `embed.FS` (a self-contained binary), target = CWD, `text/template`, a generated project that compiles, passes `go vet`, is `gofmt`-clean and answers `200` on `/health` with a graceful shutdown on `SIGTERM`.

## Findings

### Blocking

| # | Finding | Evidence | Status |
|---|---|---|---|
| 1 | `init()` in `scaffold/scaffold.go` did `panic("cannot find $GOPATH environment variable")`. `$GOPATH` is empty on every module-based setup: the CLI died at startup. The tests passed **only** because the repo was cloned in `~/go/src/github.com/…` | `panic` on the first command outside the GOPATH | ✅ fixed |
| 2 | The generation target was `filepath.Abs(filepath.Dir(os.Args[0]))`, i.e. **the binary's** directory | reproduced: `scaffold init` from an empty dir → 9 files created next to the executable, launch dir left empty | ✅ `os.Getwd()` |
| 3 | The templates were read from disk at runtime from a hardcoded GOPATH path (`GoScaffoldPath`) → a distributed binary (release, `go install`, Docker image) could not find them | `filepath.Walk` on a non-existent path, no error propagated | ✅ `embed.FS` |
| 4 | The generated project **did not compile**: 9 errors | `go build ./...` on the generated project: `"log" imported and not used`, `undefined: fmt` ×3, `undefined: env`, `undefined: strconv` ×2, `"os" imported and not used`, `undefined: http` | ✅ fixed |
| 5 | `make up` and the CLI's final message pointed to a `docker-compose.yml` that **no template generated** | `docker-compose up` → file not found | ✅ template added |

### Correctness

| # | Finding | Status |
|---|---|---|
| 6 | `html/template` used to generate **Go code**: HTML-escaping of `&&`, `<-`, struct tags. Hence the `unescaped` helper and the `data.Quit = "<-quit"` field — workarounds for the bug, not features | ✅ `text/template`, helper and field removed, regression test |
| 7 | The return value of `filepath.Walk` was **discarded** in `getTemplateSets()`: any I/O error on the templates was silent | ✅ error propagated |
| 8 | `defer src.Close()` / `defer dist.Close()` inside the `filepath.Walk` callback: the defers pile up until the end of the whole walk, not per file → fds held | ✅ closed per file |
| 9 | `os.MkdirAll(..., os.ModePerm)` = `0777` on every generated directory | ✅ `0755` dirs / `0644` files, with tests |
| 10 | Unconditional `os.Create`: a `scaffold init` in an existing project **overwrote** `cmd/main.go`, `go.mod`, `Dockerfile` without asking → lost work | ✅ `O_EXCL` + skip, overwriting only with `--force` |
| 11 | A `tmpl.Execute` error halfway through writing → truncated `.go` file left on disk | ✅ partial file removed, with a test |
| 12 | `db.tmpl` template: `log.Fatalf("error connection on %s", dsn)` — the DSN contains the **DB password** and ended up in the logs | ✅ error with host/port/name, never the DSN |
| 13 | `log.Infof("Configuration loaded ", cfg.AppEnv)` — `Infof` with no format verbs, argument discarded | ✅ structured `Infow` |
| 14 | `test/a_main_test.go`: empty `TestMain`, no tests, not `gofmt`-clean; the dir contained nothing executable | ✅ removed, real tests in `scaffold/` and `main_test.go` |
| 15 | `-o scaffold` at build time collides with the `scaffold/` package directory: Go reads `-o <dir>` as "put the binary in that directory" and writes `scaffold/Go-DDD-Scaffold` — the release tarball would have contained the sources | ✅ output in `bin/`, note in `.gitignore`/`.dockerignore` |

### Performance

| Area | Before | After | Measurement |
|---|---|---|---|
| Reading templates | `filepath.Walk` on disk in the GOPATH + `ParseFiles` (reopens and rereads every file) + two separate walks (templates, then static) with an intermediate slice | in-memory `embed.FS`, `fs.WalkDir` (no `lstat` per entry), `Parse` on the bytes already read, one pass per tree | 44 KB of assets in the binary; **4.7 ms** per generated project (average over 50 generations) |
| Creating directories | `os.MkdirAll` for **every** file (11 calls) | cache of the dirs already created (5 calls, one per directory) | −55% mkdir syscalls |
| "File exists" check | unconditional `os.Create` | `O_EXCL` — the skip is atomic, with no separate `stat` | −1 syscall per file |
| Writing | direct writes to the file | `bufio.Writer` | fewer `write()` calls per file |
| Binary | build with no flags | `-trimpath -ldflags="-s -w"` | **5.41 MB → 3.74 MB** (−31%) |
| CLI Docker image | single-stage `golang:1.18-bullseye`, ~1 GB, root, `go mod tidy` in the build (needs the network, mutates `go.sum`, invalidates the cache) | multi-stage → `alpine:3.20`, `go mod download` in its own layer before `COPY . .` | **12.2 MB** measured, deps layer cached |
| Docker build context | no `.dockerignore`: `.git`, `docs/`, `extensions/` and the 4.8 MB binary uploaded on every build | `.dockerignore` | context **15.3 kB** |
| CI | 4 duplicate jobs per push, no cache, no cancel | 1 workflow, Go cache, `cancel-in-progress`, GHA cache for the Docker layers | −50% jobs per push |
| Generated project runtime | no HTTP timeouts, pool without `ConnMaxLifetime`, no graceful shutdown, compose without a health check on the DB | `ReadTimeout`/`WriteTimeout` 15s, `ConnMaxLifetime` 1h + `ConnMaxIdleTime` 10m, `ShutdownWithTimeout(10s)` on `SIGINT`/`SIGTERM`, MySQL health check with `depends_on: service_healthy` | avoids trapped fds, dead connections after a failover and the crash loop at startup |

## Final verification

```
make check                → gofmt + go vet: clean
make test                 → ok (race enabled)
make e2e                  → 11 files generated, go mod tidy + go build + go vet + gofmt: clean
docker build              → 12.2 MB, `scaffold version audit`
docker run -v $PWD:/work  → 11 files generated into the bind mount
HTTP smoke test           → GET /health = 200, SIGTERM = graceful shutdown in ~0 ms
scaffold init ×2          → 0 created / 11 skipped (nothing overwritten)
scaffold init --force     → 11 rewritten
```

The module path is now inferred from the directory: `~/code/github.com/acme/myservice` → `module github.com/acme/myservice`. The old `module TODO/<name>` placeholder (which `go get` cannot resolve) is gone.

- **VS Code extension not working** — the biggest entry. The `extension.new-scaffold` command generates nothing:
  - `createScaffoldTemplate()` computes a `…_bloc.dart` target (**Dart**, not Go) and the `writeFile` is **commented out**;
  - `getScaffoldTemplate()` is imported nowhere, and the `src/templates/**/*.tpl` files are read by no code;
  - `workspace.getConfiguration("bloc").get("newBlocTemplate.createDirectory")` reads **another** extension's configuration namespace;
  - `createDirectoryV2()` does not await `mkdirp` → race on the dir creation;
  - logic duplicated between `extension.ts` and `commands/new-scaffold.command.ts` (the latter never registered, and it uses `mkdirp` with a callback, an API removed in mkdirp v1+);
  - `package.json`: `publisher: "None"` and `version: "0.0.1"` → publishing to the marketplaces would fail anyway.
  It is the leftover of a Flutter/BLoC generator that was adapted. It needs a rewrite, not a patch: **the owner's decision** whether to rewrite or retire it. In this pass only the twin `.tpl` templates were fixed (compilation errors, `database/db.tpl` was an identical duplicate of `config/config.tpl`) to respect the twins rule.
- **`release.yml`** uses `Allan-Nava/go-release.action@v1.5.01`, a third-party action not pinned to a SHA, and the amd64 job is labelled `macos/32`. Not touched: changing the release workflow without being able to run it is risky.
- **No linter**: `golangci-lint` is not configured. `gofmt` + `go vet` are now in CI, but they do not cover errcheck/ineffassign.
- **`config/config.yml` is not read** by the generated code (configuration comes from the environment): it stays as a container of non-secret parameters, with comments saying so. Two sources of configuration to consolidate.
- **`docs/`**: `index.md` documented a layout that never existed (`config/config.go`, `utils/api_messages.go`) — aligned. `_config.yml` had a typo in the `gh_edit_repository` repo (`Go-DDD-ScaffoldS`) and an unclosed `href` in `footer_content`, fixed.
