# Audit tecnico — 2026-08-11

Audit completo di `Go-DDD-Scaffold`: CLI, template del progetto generato, estensione VSCode, CI/CD, Docker. Ogni finding è stato **riprodotto** prima di essere corretto e **riverificato** dopo.

## Sintesi

Il generatore era **non funzionante su qualsiasi installazione moderna** e, quando riusciva a girare, **produceva un progetto che non compilava**. Tre difetti indipendenti si sommavano:

```
  scaffold init
       │
       ├─ init() del package scaffold
       │     └─ panic se $GOPATH == ""            ──►  [1] CLI morta out-of-the-box
       │
       ├─ target = filepath.Dir(os.Args[0])
       │     └─ dir del BINARIO, non la CWD      ──►  [2] file generati nel posto sbagliato
       │
       ├─ template letti da
       │     $GOPATH/src/github.com/Allan-Nava/Go-DDD-Scaffold/template/
       │     └─ assenti dopo `go install`         ──►  [3] nessun template trovato
       │
       └─ html/template su codice Go              ──►  [4] escaping dei sorgenti
              │
              ▼
        progetto generato: 9 errori di compilazione ──► [5] inutilizzabile
```

Dopo le correzioni: template in `embed.FS` (binario autosufficiente), target = CWD, `text/template`, progetto generato che compila, passa `go vet`, è `gofmt`-clean e risponde `200` su `/health` con shutdown graceful su `SIGTERM`.

## Findings

### Bloccanti

| # | Finding | Evidenza | Stato |
|---|---|---|---|
| 1 | `init()` in `scaffold/scaffold.go` faceva `panic("cannot find $GOPATH environment variable")`. `$GOPATH` è vuota su ogni setup con moduli: la CLI moriva all'avvio. I test passavano **solo** perché il repo era clonato in `~/go/src/github.com/…` | `panic` al primo comando fuori dal GOPATH | ✅ risolto |
| 2 | Il target di generazione era `filepath.Abs(filepath.Dir(os.Args[0]))`, cioè la directory **del binario** | riprodotto: `scaffold init` da una dir vuota → 9 file creati accanto all'eseguibile, dir di lancio rimasta vuota | ✅ `os.Getwd()` |
| 3 | I template erano letti da disco a runtime da un path GOPATH hardcoded (`GoScaffoldPath`) → un binario distribuito (release, `go install`, immagine Docker) non li trovava | `filepath.Walk` su un path inesistente, nessun errore propagato | ✅ `embed.FS` |
| 4 | Il progetto generato **non compilava**: 9 errori | `go build ./...` sul generato: `"log" imported and not used`, `undefined: fmt` ×3, `undefined: env`, `undefined: strconv` ×2, `"os" imported and not used`, `undefined: http` | ✅ risolto |
| 5 | `make up` e il messaggio finale della CLI rimandavano a un `docker-compose.yml` che **nessun template generava** | `docker-compose up` → file non trovato | ✅ template aggiunto |

### Performance

| Area | Prima | Dopo | Misura |
|---|---|---|---|
| Lettura template | `filepath.Walk` su disco nel GOPATH + `ParseFiles` (riapre e rilegge ogni file) + due camminate separate (template, poi static) con slice intermedia | `embed.FS` in memoria, `fs.WalkDir` (nessun `lstat` per entry), `Parse` sui byte già letti, singola passata per albero | 44 KB di asset nel binario; **4,7 ms** per progetto generato (media su 50 generazioni) |
| Creazione directory | `os.MkdirAll` per **ogni** file (11 chiamate) | cache delle dir già create (5 chiamate, una per directory) | −55% syscall di mkdir |
| Check "file esiste" | `os.Create` incondizionata | `O_EXCL` — lo skip è atomico, senza `stat` separato | −1 syscall per file |
| Scrittura | scrittura diretta sul file | `bufio.Writer` | meno `write()` per file |
| Binario | build senza flag | `-trimpath -ldflags="-s -w"` | **5,41 MB → 3,74 MB** (−31%) |
| Immagine Docker CLI | single-stage `golang:1.18-bullseye`, ~1 GB, root, `go mod tidy` in build (richiede rete, muta `go.sum`, invalida la cache) | multi-stage → `alpine:3.20`, `go mod download` in layer separato prima di `COPY . .` | **12,2 MB** misurati, layer deps cacheato |
| Contesto di build Docker | nessun `.dockerignore`: `.git`, `docs/`, `extensions/` e il binario da 4,8 MB caricati a ogni build | `.dockerignore` | contesto **15,3 kB** |
| CI | 4 job duplicati per push, nessuna cache, nessun cancel | 1 workflow, cache Go, `cancel-in-progress`, cache GHA per i layer Docker | −50% job per push |
| Runtime del progetto generato | nessun timeout HTTP, pool senza `ConnMaxLifetime`, nessuno shutdown graceful, compose senza healthcheck sul DB | `ReadTimeout`/`WriteTimeout` 15s, `ConnMaxLifetime` 1h + `ConnMaxIdleTime` 10m, `ShutdownWithTimeout(10s)` su `SIGINT`/`SIGTERM`, healthcheck MySQL con `depends_on: service_healthy` | evita fd trappolati, connessioni morte dopo un failover e il crash-loop all'avvio |

## Debito residuo

Non risolto in questo passaggio, con motivazione.

- **Estensione VSCode non funzionante** — è la voce più grossa. Il comando `extension.new-scaffold` non genera nulla:
  - `createScaffoldTemplate()` calcola un target `…_bloc.dart` (**Dart**, non Go) e la `writeFile` è **commentata**;
  - `getScaffoldTemplate()` non è importato da nessuna parte, e i file `src/templates/**/*.tpl` non sono letti da alcun codice;
  - `workspace.getConfiguration("bloc").get("newBlocTemplate.createDirectory")` legge un namespace di configurazione di un'**altra** estensione;
  - `createDirectoryV2()` non attende `mkdirp` → race sulla creazione della dir;
  - logica duplicata tra `extension.ts` e `commands/new-scaffold.command.ts` (quest'ultimo mai registrato, e usa `mkdirp` con callback, API rimossa in mkdirp v1+);
  - `package.json`: `publisher: "None"` e `version: "0.0.1"` → il publish sui marketplace fallirebbe comunque.
  È il residuo di un generatore Flutter/BLoC riadattato. Serve una riscrittura, non una patch: **decisione del proprietario** se riscriverla o dismetterla. In questo passaggio sono stati corretti solo i template `.tpl` gemelli (errori di compilazione, `database/db.tpl` era un duplicato identico di `config/config.tpl`) per rispettare la regola dei gemelli.
- **`release.yml`** usa `Allan-Nava/go-release.action@v1.5.01`, action di terze parti non pinnata a SHA, e il job amd64 è etichettato `macos/32`. Non toccato: modificare il workflow di release senza poterlo eseguire è rischioso.
- **Nessun linter**: `golangci-lint` non è configurato. `gofmt` + `go vet` sono ora in CI, ma non coprono errcheck/ineffassign.
- **`config/config.yml` non è letto** dal codice generato (la configurazione arriva dall'ambiente): resta come contenitore di parametri non segreti, con commenti che lo dichiarano. Doppia fonte di configurazione da consolidare.
- **`docs/`**: `index.md` documentava un layout mai esistito (`config/config.go`, `utils/api_messages.go`) — allineato. `_config.yml` ha un typo nel repo di `gh_edit_repository` (`Go-DDD-ScaffoldS`) e un `href` non chiuso nel `footer_content`, corretti.
